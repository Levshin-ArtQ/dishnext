# Что поесть?

Подбор ужина на русском: короткие свайпы, прозрачное ранжирование и турнир блюд. Без аккаунта, без опроса и без ключей API в браузере.

Личное приложение в том же духе, что Hours, Planin и «Мой Пекин»: статический хостинг, IndexedDB, PWA. Стек экрана — React + TypeScript + Vite, как в ТЗ `DishNext.docx`.

## Запуск

```bash
cd grok_env/dishnext
npm install
npm start          # http://localhost:8772
npm test
npm run build
```

iPhone: Safari → Поделиться → На экран «Домой». После первого онлайн-визита оболочка и каталог открываются офлайн. Фото TheMealDB и внешние рецепты могут требовать сеть.

Живая версия: [dishnext.vercel.app](https://dishnext.vercel.app). Репозиторий `Levshin-ArtQ/dishnext`; пуш в `main` собирает Vercel. Framework **Vite**, `vercel.json` задаёт заголовки для service worker.

## Как устроен вечер

1. Режим: «Быстрый ужин», «Поискать новое» или «Сравнить два».
2. Короткий экран: настроение (правильное питание / сытные блюда), направление кухни (итальянская, русская и другие; пустой выбор — любая), что есть дома, чего не класть, что хочется добавить.
3. Карточки: «Не это», «Пропустить», «Очень хочу», «Берём». «Готовим это» сразу открывает рецепт.
4. Сравнение двух блюд, если отметили несколько. «Оба нравятся» оставляет обоих.
5. Экран готовки: что уже есть, что докупить, меры, шаги источника по одному.

Дома чаще всего курица и свинина — каталог и ранжирование это учитывают.

## Правки перевода

На домашнем экране кнопка **Каталог**. Список по умолчанию показывает блюда с латиницей в русском названии. На компьютере с `npm start` кнопка **Записать в каталог** пишет `public/data/overrides.json`, и карточки сразу берут новые имена. **Выложить на сайт** делает `git commit` и `git push` — Vercel подхватывает `main`.

Пересборка каталога (`npm run catalog`) накладывает те же правки поверх свежего дампа, так что ручные имена не пропадают.

## Данные

Каталог — подготовленный JSON из [TheMealDB](https://www.themealdb.com) (`public/data/catalog.json`). Импорт:

```bash
# нужен дамп писем API в /tmp/dishnext/letters
python3 scripts/build_catalog.py
```

Скрипт ходит к API только при сборке каталога. В клиент ключи не попадают. Превью блюд лежат в `public/thumbs/` (собираются `npm run thumbs`), чтобы карточки открывались без ожидания TheMealDB. Оригинал и атрибуция остаются у источника. Шаги рецепта не переводятся и не выдумываются.

Пользовательские данные (сессия, вкус, избранное, история) — IndexedDB `dishnext-private`, запасной путь localStorage. Два телефона не синхронизируются.

## Алгоритм

Жёсткие фильтры применяются до ранжирования. Затем

`S(d) = wp·P + wc·C + wn·N + wv·V − wr·R`

где P — явные предпочтения, C — контекст режима, N — новизна, V — разнообразие колоды, R — штраф за недавний повтор. Один свайп влево не трактуется как нелюбовь ко всей кухне. Веса и доля исследования настраиваются в «Вкусы».

## Решения по умолчанию

- Колода: 10 / 16 / 12 карточек для трёх режимов.
- Исследование: 25% колоды в режиме «интересное», меньше в быстром.
- Время, сложность и бюджет — оценки по составу и длине рецепта, не факты источника.
- Турнир не строит глобальный рейтинг Elo; это сравнение «сегодня».
- Дизайн новый: тёплый editorial-журнал, а не оболочка Planin / Hours / «Мой Пекин».
